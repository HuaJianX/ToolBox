# 一、MVP 界面草图

窗口 960 × 800，最小 780 × 640，居中启动，字体「微软雅黑 UI」，单列布局，不用多级菜单。
整个程序只有**两个页面**：首页 → 转换页。转换页永远是「选文件 → 选格式 → 开始」三步。

## 屏幕 3：转换中

底部那块原地换成进度，界面其它部分不动（不会跳来跳去）：

```
├────────────────────────────────────────────────────────────────┤
│  正在转换第 2 / 3 个：合影.png                                  │
│   ████████████████████████░░░░░░░░░░░░░░░░░░░░░░   64%         │
│   正在转换图片…                                                 │
│   ┌────────┐                                                   │
│   │  取消  │                                                   │
│   └────────┘                                                   │
└────────────────────────────────────────────────────────────────┘
```

- 进度条能算就算（音视频用 ffprobe 读出总时长再算百分比），**算不出来就显示来回滚动的
  条纹**，绝不假装一个假的百分比。
- 「取消」随时能点，点了会**杀掉整棵进程树**，不留后台残留，已经转好的文件保留。

按钮只有一个主行动：**打开文件夹**，点了直接弹出资源管理器并定位到产出文件。

## 出错时长什么样

错误**不弹窗**，就换掉底部那块文字，颜色转红，用户不用去关任何对话框：

```
├────────────────────────────────────────────────────────────────┤
│   没转成功                                                      │
│   假期照片.psd：这个文件打不开，可能坏了或者不是真正的图片，     │
│   换一个试试。                                                  │
└────────────────────────────────────────────────────────────────┘
```

四种典型人话（都在 `FriendlyError.cs` 里，一处改全局生效）：

| 技术原因 | 用户看到的话 |
|---|---|
| 文件损坏 / 不是真图片 | 这个文件打不开，可能坏了或者不是真正的图片，换一个试试。 |
| 磁盘空间不足 | 磁盘空间不够了，清理一点空间再试。 |
| 文件被别的程序占用 | 这个文件正被别的程序用着，先关掉它再试。 |
| 缺少转换组件 | 这台电脑还缺一个转换组件：FFmpeg（音视频转换）。把它放进程序目录的 tools 文件夹里就能用了。 |
| PDF 是扫描件 | 这个 PDF 是扫描件，里面没有可以直接取的文字。可以改用「PDF 转图片」…… |

## 设计约束是怎么落到界面上的

| 你的要求 | 界面上的做法 |
|---|---|
| 首页只有几个大按钮 | 只有 5 个大按钮，没有侧边栏、没有菜单栏、没有标签页 |
| 每次最多 3 步 | 页面上直接写「第 1 步 / 第 2 步 / 第 3 步」 |
| 默认格式自动推荐 | 按源文件后缀自动选好（HEIC 进来就自动选 JPG），还带「推荐」绿字 |
| 高级选项藏起来 | 干脆没有。不设质量、码率、分辨率 —— 参数都写死在代码里选稳妥值 |
| 中文大白话 | 「只要声音（MP3）」而不是「提取音频轨」；「不要这个」而不是「移除」 |
| 大字体高对比 | 正文 17–19px，按钮 22–30px，标题 28–44px；深蓝字 `#0D2A4A` 配白底 |
| 单列布局 | 所有内容都在中间一列，最大宽度 820px，不并排 |
| 完成显示「转换好了」 | 大字 🎉 转换好了 + 一键打开文件夹 |
| 不覆盖原文件 | 输出固定到「转换结果」文件夹，重名自动加序号 |
| 转换时界面不卡 | 解码/编码在线程池，外部组件用异步读流，界面线程只更新一个进度条 |
